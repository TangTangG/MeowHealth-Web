# AI 化验单分析模块与 Dashboard 概览交互设计规范 (Specs)

## 1. 核心设计理念：方案三 + 方案二融合
- **主界面 (方案三)**：卡片仪表盘式 UI。侧重结构化数据的清晰展示、异常高亮与历史趋势图表联动，提供全局掌控感。
- **辅助增强 (方案二)**：对话陪伴式悬浮助手。用户在查看结构化报告时，可随时唤起针对当前报告的追问（答疑解惑）。

## 2. Dashboard 概览页设计 (`/dashboard`)
Dashboard 作为用户登录后的全局集散中心，需提供系统性的健康状态总览。

### 2.1 顶部全局操作区
- **欢迎语**：显示用户昵称及宠物昵称。
- **快捷操作按钮**：
  - **记录流水**：快速唤起健康事件记录弹窗。
  - **上传化验单分析**：高亮主按钮，触发上传区域。

### 2.2 化验单上传入口
- 独立于页面顶部的**蓝色虚线拖拽上传区**。
- 支持拖拽或点击选择 **PDF, JPG, PNG** 多文件上传。
- 附带智能标签（"血常规", "生化全项", "尿检报告"）引导分类。

### 2.3 主内容区布局 (响应式两列)
**左侧主列 (宽 2/3)**：
- **待办提醒模块 (UNNotificationManager Web 映射)**：
  - 置顶优先展示。
  - 到期时间越近，提醒颜色越深（如 3 天内到期为橙色高警，更长时间为灰色提示）。
  - 支持直接“标记完成”。
- **体重趋势图 (SwiftCharts Web 映射)**：
  - 展示当前选中猫咪的历史体重折线图，带有最新体重数值展示。
  - 支持时间轴交互（如鼠标悬停显示具体日期体重）。

**右侧副列 (宽 1/3)**：
- **最近 AI 化验报告摘要**：
  - 显示最近一次体检的 AI 一句话结论。
  - 异常指标文本高亮，提供"查看完整分析详情"跳转入口。
- **近期健康事件流水 (Timeline)**：
  - 时间轴形式展示最近的健康相关事件（呕吐、疫苗驱虫、剪指甲等）。
  - 不同类型事件使用不同颜色标记。

### 2.4 猫咪档案切换
- 侧边栏顶部嵌入"猫咪切换器"，显示当前激活猫咪的头像、昵称、品种及年龄，点击可展开切换 (支持多猫家庭)。

## 3. 报告详情页设计 (`/reports/:id`)

### 3.1 报告详情页 (主界面)
- **顶部概览区**：
  - 一句话核心结论（由 AI 生成，例如："总体健康，但肌酐偏高，需注意饮水量"）。
  - 报告基础信息（日期、猫咪、诊断类型）。
  - "查看原件"按钮：点击弹出 Modal 预览原图/PDF。
- **数据卡片区 (按系统分类)**：
  - **默认折叠/展开逻辑**：存在异常指标的分类（如：肾脏功能）默认展开，全正常的分类默认收起。
  - **异常高亮**：超出正常参考值的指标使用红色/黄色块醒目标注，并附上下箭头。
- **趋势图表 (动态插入)**：
  - 对于同一指标，若存在历史数据，点击该指标直接在卡片下方内联展开 ECharts 折线图（对应 iOS 端 SwiftCharts 逻辑），直观展示变化趋势。

### 3.2 悬浮对话助手 (辅助侧边栏 / 悬浮球)
- **常驻入口**：在报告详情页右下角悬浮。
- **上下文感知**：点开即自动加载当前这份化验单的上下文。
- **快捷 Prompt 建议**：
  - "肌酐 200 严重吗？"
  - "建议换什么处方粮？"
  - "对比上个月，情况有恶化吗？"
- **交互形式**：支持自然语言的多轮对话，由 Gemini 针对该报告及其历史数据进行详细解答。

## 5. 技术实现考量
- **前端结构**：
  - 主视图使用 React Router 独立页面 `/` (Dashboard) 与 `/reports/:id`。
  - 对话助手实现为全局可唤起的 Drawer/Modal，状态交由 Zustand 管理，确保在报告页内外均能合理保持上下文。
- **后端接口支持**：
  - 除了基础的 CRUD，需新增专门针对某份报告的对话 API：`POST /api/v1/ai/chat/{report_id}`，将结构化数据作为上下文随 Prompt 一同发送给 Gemini。
